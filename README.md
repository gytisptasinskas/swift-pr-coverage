# Swift PR Code Coverage

Reports which added or changed Swift lines in a pull request were not executed by any test. It reads the `.xcresult` bundles from a [Tuist](https://tuist.dev) project's test run, intersects their per-line coverage with `git diff`, and prints the uncovered lines grouped by file.

> **Status:** the command-line tool works locally. The GitHub Action (sticky PR comment and job summary) is in progress.

## Requirements

- macOS with Xcode (uses `xcrun xccov`) and Swift 6.
- Code coverage enabled on the scheme your tests run with. With no scheme argument, `tuist test` runs the `<Name>-Workspace` scheme, so add a `Workspace.swift`:

  ```swift
  import ProjectDescription

  let workspace = Workspace(
      name: "MyApp",
      projects: ["."],
      generationOptions: .options(
          autogeneratedWorkspaceSchemes: .enabled(codeCoverageMode: .relevant)
      )
  )
  ```

  You can also run `tuist test -- -enableCodeCoverage YES`. `.relevant` is preferred because it instruments only the targets under test, so test files stay out of the report.

## Local usage

```bash
tuist test --result-bundle-path build/Tests.xcresult
swift run swift-pr-coverage --xcresult build/Tests.xcresult --base origin/main
```

```
Diff coverage: 7 of 25 changed executable lines covered (28.0%).

Example/App/Sources/CartModel.swift        1/4 covered
  uncovered: L19–L21
Example/Core/Sources/Calculator.swift      6/6 covered
Example/Core/Sources/PriceFormatter.swift  0/15 covered
  uncovered: L30–L45

No coverage data (cached, skipped or not instrumented):
  Example/Core/Tests/CoreTests.swift
```

| Option | Default | |
|---|---|---|
| `--xcresult <path>` | required | Repeat it to merge several bundles. The highest count per line wins. |
| `--base <ref>` / `--head <ref>` | `origin/main` / `HEAD` | The tool diffs `base...head`, starting from their merge base. |
| `--diff <file>` | | Reads a ready-made `git diff --unified=0` from a file instead of running git. |
| `--repo-root <path>` | git top level | The directory that diff paths are relative to. |
| `--exclude <glob>` | | Repeatable, e.g. `'**/Tests/**'`. `**` matches any number of directories. |
| `--no-default-excludes` | | Turns off the default excludes: `**/Derived/**`, `**/Project.swift`, `**/Workspace.swift`, `**/Tuist.swift`, `**/Tuist/**`. |
| `--output text\|json` | `text` | |

How lines are counted:
- A changed line is **covered** if it ran at least once.
- It is **uncovered** if it is executable and never ran.
- Blank lines, comments and declarations don't count either way.
- Files missing from every bundle are listed separately; they are never counted as 0%. Tuist's binary cache and selective testing leave modules out of the report this way.
- If no bundle exists (selective testing had nothing to run), the tool says no tests ran and exits 0.

The tool exits non-zero only on tool errors, such as a bundle without coverage data, a failed `git diff`, or unreadable `xccov` output.

## Development

```bash
swift build
swift test
```

The core logic (`Sources/PRCoverageCore`) does no I/O. Its tests run on fixtures captured from `Example/`, a small Tuist app. See [Tests/PRCoverageCoreTests/Fixtures/README.md](Tests/PRCoverageCoreTests/Fixtures/README.md).
